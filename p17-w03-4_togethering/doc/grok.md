### 프로젝트 기획 개요

이 웹 서비스 아이디어는 소규모 그룹(커플 또는 2~4명)을 대상으로 한 프로젝트, 일정, 이벤트 관리 도구입니다. 기존의 대형 프로젝트 관리 도구(Trello, Asana 등)는 대규모 팀에 최적화되어 있지만, 이 서비스는 친밀하고 간단한 관계 중심으로 설계하여 사용성을 강조합니다. 서비스 이름으로는 "GroupSync" 또는 "CoupleHub" 같은 직관적인 이름을 제안합니다. 목표는 사용자들이 복잡한 기능 없이 직관적으로 협업할 수 있게 하는 것입니다.

#### 1. 타겟 사용자 분석
- **주요 타겟**: 
  - 커플: 로맨틱한 관계에서 공유 일정(데이트, 여행 계획)이나 공동 프로젝트(집안 일, 선물 준비)를 관리.
  - 소규모 그룹: 친구나 가족(2~4명)으로, 모임 계획, 스터디 그룹, 소규모 이벤트(파티, 여행)를 위한 도구.
- **사용자 페르소나 예시**:
  - 커플: 20~30대 젊은 커플, 바쁜 일상 속에서 서로의 일정을 공유하고 싶은 사용자.
  - 그룹: 대학생 스터디 그룹이나 가족 모임, 간단한 협업이 필요한 비즈니스 파트너.
- **문제점 해결**: 기존 캘린더 앱(Google Calendar)은 공유가 복잡하고, 프로젝트 도구는 과도한 기능으로 인해 소규모 그룹에 부담. 이 서비스는 모바일 우선으로 간단한 UI를 제공하여 접근성을 높임.

#### 2. 핵심 기능 상세
기능은 프로젝트 관리, 일정 관리, 이벤트 관리를 중심으로 하되, 소규모 그룹의 친밀함을 반영하여 알림, 공유, 커뮤니케이션 요소를 통합합니다. MVP(Minimum Viable Product) 단계에서 필수 기능만 구현하고, 추후 확장.

| 기능 카테고리 | 세부 기능 | 설명 | 우선순위 |
|--------------|----------|------|----------|
| **그룹 생성 및 관리** | 그룹 생성 | 초대 링크나 이메일/전화번호로 2~4명 그룹 생성. 커플 모드로 자동 2인 그룹 설정. | 높음 |
| | 멤버 관리 | 멤버 추가/제거, 역할 부여(예: 리더가 일정 승인). | 높음 |
| **프로젝트 관리** | 태스크 리스트 | 간단한 To-Do 리스트 생성(예: "여행 준비" 프로젝트에 "항공권 예매", "호텔 검색" 태스크). 체크박스, 마감일 설정. | 높음 |
| | 프로그레스 트래킹 | 진행률 바(percentage), 댓글 기능으로 피드백 공유. | 중간 |

| **일정 관리** | 캘린더 뷰 | 공유 캘린더(일/주/월 뷰), 색상 코딩으로 개인/그룹 일정 구분. | 높음 |
| | 리마인더 | 푸시 알림, 이메일/SMS 알림(예: "오늘 데이트 1시간 전"). | 높음 |
| | 동기화 | Google Calendar, iCalendar와 연동. | 중간 |
| **이벤트 관리** | 이벤트 생성 | 이벤트 카드(날짜, 장소, 참석자, 메모). 지도 연동(Google Maps)으로 장소 추천. | 높음 |
| | 투표/의사결정 | 이벤트 옵션 투표(예: "어느 레스토랑 갈까?"). | 중간 |
| | 추억 공유 | 이벤트 후 사진 앨범 생성, 자동 타임라인. | 낮음 |
| **기타 기능** | 채팅 통합 | 간단한 실시간 채팅(Slack-like, 하지만 가벼움). | 중간 |
| | 테마 커스터마이징 | 커플 테마(하트 아이콘), 그룹 테마(컬러 선택). | 낮음 |
| | 데이터 백업 | 클라우드 백업, 내보내기 기능. | 낮음 |

- **보안 및 프라이버시**: 그룹 내 데이터는 암호화, 초대된 멤버만 접근. GDPR 준수.

#### 3. 사용자 흐름 (User Journey)
1. **온보딩**: 앱/웹 접속 → 계정 생성(이메일/SNS 로그인) → 그룹 유형 선택(커플/그룹) → 초대.
2. **메인 대시보드**: 그룹 목록 → 선택 시 캘린더 + 프로젝트 보드 표시.
3. **기능 사용 예시**:
   - 커플: "주말 여행" 프로젝트 생성 → 태스크 할당(남자: 항공권, 여자: 호텔) → 일정 등록 → 이벤트 알림.
   - 그룹: "스터디 모임" → 일정 공유 → 태스크(자료 준비) → 이벤트(온라인 미팅 링크).
4. **오프보딩**: 그룹 해체 시 데이터 삭제 옵션.

#### 4. 기술 스택 제안
- **프론트엔드**: React.js (웹) + React Native (모바일 앱)으로 크로스플랫폼 지원.
- **백엔드**: Node.js/Express 또는 Python/Django, 실시간 기능 위해 Socket.io.
- **데이터베이스**: MongoDB (유연한 문서 기반) 또는 PostgreSQL (관계형).
- **클라우드**: AWS 또는 Firebase (푸시 알림, 인증 용이).
- **통합**: Google API (캘린더, Maps), Twilio (SMS 알림).
- **개발 접근**: Agile 방법론, MVP 3개월 개발 목표.

#### 5. 비즈니스 모델 및 마케팅
- **수익화**: 무료 기본 버전 + 프리미엄(월 1,000원): 무제한 그룹, 광고 제거, 고급 테마, 우선 지원.
- **마케팅**: 
  - 타겟 채널: Instagram/TikTok (커플 콘텐츠), Reddit (소규모 그룹 커뮤니티).
  - 파트너십: 데이트 앱(Between)과 연동.
  - 런치 전략: 베타 테스트(100명 그룹) → 피드백 반영 → App Store/Google Play 출시.
- **위험 및 대응**: 경쟁(기존 앱) → 차별화(소규모 특화). 사용자 유지 → 주기적 업데이트(새 테마, 기능).

이 기획은 아이디어를 바탕으로 한 초기안으로, 사용자 피드백을 통해 迭代할 수 있습니다. 추가 세부 사항(예: UI 디자인 mockup)이 필요하시면 말씀해주세요!

### 5. 주요 화면 UI/UX 상세 가이드

#### 5-1. 온보딩 (첫 실행 3초 룰)
1. 첫 화면: 큰 하트 + “우리만의 작은 계획” 한 줄  
2. 두 번째 슬라이드: “커플이에요 / 친구·가족이에요” 2개 큰 버튼  
3. 로그인: 카카오·구글·애플 3개만 노출, 이메일은 “다른 방법” 접기  

#### 5-2. 홈 대시보드 (가장 중요한 화면)
- 상단: 그룹 대표 사진 둥글게 + 그룹명 + 오늘의 기념일/D-day 카운트  
- 중앙 70%: 오늘·내일의 일정 + 진행 중 프로젝트 한눈에 (카드 스크롤)  
- 하단 고정 탭바 (4개):  
  홈 │ 캘린더 │ 프로젝트 │ 채팅  

#### 5-3. 캘린더 뷰
- 기본: 월간 뷰 (가장 많이 쓰는 뷰를 첫 화면으로)  
- 일정 도트 대신 하트(커플) 또는 색상 원으로 표시  
- 길게 누르면 바로 새 일정 추가 (모달이 아닌 인라인 추가)  
- 상단에 “오늘” 버튼 항상 노출  

#### 5-4. 프로젝트 보드
- 기본 3칸: 할 일 / 진행 중 / 완료  
- 카드 디자인: 좌측 색상 바 (담당자 색상) + 제목 + 체크리스트 진행률 + 마감일  
- 드래그 앤 드롭 시 부드러운 스프링 애니메이션  

#### 5-5. 이벤트 상세 화면
- 상단 큰 이미지 (없으면 장소 사진 자동 크롤링)  
- 중간: 날짜·시간·장소(지도 미리보기)  
- 하단 탭: 정보 / 채팅 / 투표 / 사진첩  

#### 5-6. 채팅
- 카카오톡 느낌 + 약간의 Between 감성  
- 입력창 위에 빠른 이모지 6개 (♥️, 😂, 😍, 👍, 🎉, 🥳)  
- 상대방이 입력 중이면 “OOO님이 입력 중...” 하트 애니메이션과 함께  

### 6. 마이크로 인터랙션 (감성 포인트)
- 태스크 완료 체크 → 하트 파티클 5개 터짐

### 1. 개요 및 설계 원칙
이 문서는 Together 앱의 MVP 개발을 위한 기술 스택을 명세합니다. 모든 구성 요소는 **로컬 환경 100%**를 준수하며, 클라우드 서비스(AWS, Firebase, Google API 등)나 외부 웹서비스를 사용하지 않습니다. 개발/테스트/배포는 개발자 로컬 머신에서만 가능하도록 설계되었으며, 프로덕션 배포 시에도 온프레미스 서버(로컬 네트워크)에서 실행 가능합니다.

- **주요 고려사항**:
  - 오프라인/로컬 우선: 데이터 저장은 로컬 파일 기반 DB, 실시간 기능은 로컬 서버 내 Socket 기반.
  - 크로스플랫폼: 웹(React)과 모바일(React Native) 지원, 하지만 모바일 빌드는 로컬 에뮬레이터에서만 테스트.
  - 보안: 로컬 환경이므로 HTTPS는 self-signed 인증서로 대체 (개발 시).
  - 확장성: MVP 기준 소규모(2~4명 그룹)이므로, 로컬 DB로 충분.

- **전체 아키텍처**:
  - **프론트엔드**: React (웹) + React Native (모바일 앱).
  - **백엔드**: Node.js + Express (REST API + 실시간 Socket).
  - **데이터베이스**: SQLite (로컬 파일 기반, 관계형 데이터에 적합).
  - **빌드/도구**: Vite (React), Metro (React Native), npm/yarn (패키지 관리).
  - **통합**: Google Maps 연동 대신 오픈소스 로컬 지도 라이브러리 (Leaflet with local tiles, but MVP에서 지도 기능은 텍스트 기반 장소로 대체).
  - **알림**: 웹 푸시(브라우저) 또는 로컬 노티피케이션 (모바일), 서버 푸시 없음.

### 3. 개발 환경 설정 가이드 (로컬 100%)
1. **필수 설치**:
   - Node.js 24.12.0: [공식 다운로드](https://nodejs.org/).
   - Android Studio (모바일 에뮬레이터) 또는 Xcode (iOS, Mac 한정).
   - SQLite 또는 PostgreSQL 로컬 바이너리.

2. **프로젝트 구조 예시**:
   ```
   together-mvp/
   ├── frontend-web/     # React + Vite
   ├── frontend-mobile/  # React Native
   ├── backend/          # Node.js + Express + Socket.io
   │   ├── db/           # SQLite 파일 (.db)
   │   └── server.js
   ├── shared/           # 공통 타입/유틸 (TypeScript)
   └── package.json      # 루트에서 monorepo 관리 (yarn workspaces)
   ```

3. **실행 명령어**:
   - 백엔드: `cd backend && node server.js` (포트 3001).
   - 웹 프론트: `cd frontend-web && npm run dev` (포트 3000, 백엔드 proxy).
   - 모바일: `cd frontend-mobile && npx react-native run-android` (로컬 에뮬레이터).

4. **제약 및 대응**:
   - 푸시 알림: 모바일은 로컬 노티피케이션 API 사용, 웹은 Service Worker (브라우저 로컬).
   - 파일 공유: 로컬 파일 시스템 접근 (Node.js fs 모듈).
   - 동기화: Google Calendar 연동 없음; 로컬 DB만 사용.
   - 보안: 로컬 네트워크에서만 접근 (firewall 설정).

### 4. 버전 관리 및 업데이트 정책
