# 꼬박 (Habit Builder) 제품 요구사항 명세서 (Product Requirements Document, PRD)

## 1. 개요 (Introduction)

### 1.1 문서 목적
이 문서는 '꼬박' 플랫폼의 제품 요구사항을 명확히 정의하여 개발팀, 디자인팀, 및 관련 이해관계자들이 동일한 이해를 기반으로 프로젝트를 진행할 수 있도록 합니다. '꼬박'은 사용자에게 친근하고 인터랙티브한 경험을 제공하는 습관 형성 챌린지 웹 플랫폼으로, 습관 설정, 추적, 피드백, 동기 부여를 핵심 기능으로 합니다. 이 명세서는 기획안 초안을 바탕으로 기능, 디자인, 인터랙션 요소를 체계적으로 정리합니다.

### 1.2 프로젝트 범위 (Scope)
- **포함 범위**: 웹 기반 플랫폼 (모바일 최적화 포함). 주요 화면: 대시보드, 습관 설정/수정, 히스토리/분석. 마스코트 '꼬바기', 습관 나무 메타포, 인터랙티브 애니메이션 구현.
- **제외 범위**: 모바일 네이티브 앱 개발, 고급 AI 기반 추천 기능, 결제 시스템 (수익 모델은 별도 정의).
- **대상 사용자**: 습관 형성을 원하는 일반 성인 사용자 (친근한 톤앤매너로 모든 연령대 접근 가능).
- **플랫폼명**: 꼬박 (Kkobak).
- **톤앤매너**: 친근함, 격려, 긍정적, 활기참, 미니멀.

### 1.3 용어 정의
- **꼬바기**: 플랫폼 마스코트 캐릭터 (작은 새싹 또는 털뭉치 형태, 표정/모션 변화로 사용자 피드백 제공).
- **습관 나무**: 습관 진행 상황을 시각화하는 메타포 (체크 시 성장 모션 적용).
- **스트릭**: 연속 성공 일수 (Streak).
- **데일리 체크**: 일일 습관 완료 기록.

### 1.4 가정 및 제약
- **가정**: 사용자는 웹 브라우저 (Chrome, Safari 등)를 통해 접근. 클라우드 기반 데이터 저장 (e.g., Firebase).
- **제약**: 초기 버전은 웹 중심. 보안: 사용자 데이터 암호화 필수. 예산/시간: 필수 기능 우선 개발.

## 2. 사용자 요구사항 (User Requirements)

### 2.1 사용자 페르소나
- **주요 사용자**: 20-40대 직장인/학생. 습관 형성 동기 부여 필요 (e.g., 운동, 독서, 물 마시기).
- **니즈**: 쉬운 습관 설정, 즉각적 피드백, 재미있는 인터랙션, 동기 유지 알림.
- **페인 포인트**: 기존 앱의 딱딱한 UI, 동기 상실, 기록 수정 어려움.

### 2.2 사용자 시나리오
- **시나리오 1**: 신규 사용자 가입 후 습관 생성 → 데일리 체크 → 꼬바기 축하 모션 확인.
- **시나리오 2**: 기존 사용자 로그인 → 대시보드에서 스트릭 확인 → 실패 시 격려 메시지 수신.
- **시나리오 3**: 히스토리 화면에서 과거 기록 분석 → 습관 수정.

## 3. 기능 요구사항 (Functional Requirements)

기획안의 필수 기능을 기반으로 분류. 각 기능은 우선순위 (High/Medium/Low) 표시.

### 3.1 회원 관리
- **F1.1 회원가입/로그인** (High): 이메일, 소셜 로그인 (Google, Kakao 등) 지원. 비밀번호 재설정 기능.
- **F1.2 프로필 관리** (Medium): 사용자 이름, 프로필 이미지 설정. 데이터 동기화 (클라우드 백업).

### 3.2 습관 설정 및 관리
- **F2.1 습관 생성** (High): 습관 이름, 아이콘 선택, 반복 요일 (매일/특정 요일), 목표 기간 (e.g., 30일 챌린지), 빈도 (횟수/시간), 알림 시간/텍스트 설정.
- **F2.2 습관 수정/삭제** (High): 기존 습관 항목 변경/삭제. 꼬바기 반응 애니메이션 적용.
- **F2.3 커스터마이징** (Medium): 습관 아이콘/색상, 알림 소리 사용자 설정.

### 3.3 습관 추적
- **F3.1 데일리 체크** (High): 대시보드에서 원터치 체크. 체크 시 애니메이션 (e.g., 잎사귀 성장, 꼬바기 박수) 및 사운드.
- **F3.2 기록 수정** (High): 과거 날짜 소급 수정 (스트릭 유지 보장).
- **F3.3 스트릭 추적** (High): 연속 기록 표시 (아이콘 반짝임 모션).

### 3.4 피드백 및 시각화
- **F4.1 대시보드 현황** (High): 오늘 습관 리스트, 달성률 (도넛 차트), 습관 나무 시각화, 꼬바기 반응.
- **F4.2 히스토리 분석** (High): 캘린더 뷰 (성공/실패 색상 표시), 라인 차트 (달성률 변화), 누적 통계.
- **F4.3 격려 메시지** (High): 상황별 변동 메시지 (e.g., 성공: "대단해요!", 실패: "괜찮아요.").

### 3.5 동기 부여
- **F5.1 맞춤 알림** (High): 푸시 알림 (웹 푸시 지원). 꼬바기 스타일 텍스트.
- **F5.2 성취 피드백** (High): 목표 달성 시 모션 그래픽 (e.g., 꽃 피는 애니메이션), 뱃지/레벨 시스템.
- **F5.3 커뮤니티 기능** (Medium): 챌린지 공유, 좋아요/격려 버튼, 습관 카드 SNS 공유.

### 3.6 시스템 지원
- **F6.1 데이터 동기화** (High): 여러 기기 간 실시간 동기.
- **F6.2 로딩/전환 효과** (Medium): 부드러운 페이드 인/아웃, 꼬바기 등장 모션.

## 4. 비기능 요구사항 (Non-Functional Requirements)

### 4.1 성능
- 페이지 로딩 시간: 2초 이내.
- 애니메이션: 60fps 유지 (브라우저 호환성 고려).
- 스케일링: 초기 1,000명 사용자 지원, 클라우드 확장 가능.

### 4.2 보안 및 프라이버시
- 데이터 암호화: 사용자 습관 데이터 HTTPS 전송, 저장 시 암호화.
- GDPR 준수: 개인정보 동의, 삭제 기능.
- 인증: JWT 기반 세션 관리.

### 4.3 사용성 (Usability)
- 접근성: WCAG 2.1 준수 (색맹 지원, 키보드 네비게이션).
- 모바일 최적화: Responsive Design (하단 탭 바 활용).
- 다국어: 초기 한국어 지원, 영어 확장 가능.

### 4.4 신뢰성
- 백업: 일일 자동 백업.
- 오류 처리: 친근한 오류 메시지 (e.g., "앗, 잠깐!").

### 4.5 유지보수성
- 모듈화: 기능별 컴포넌트 분리.
- 로그: 사용자 행동 로그 수집 (분석 용도).

## 5. 디자인 및 UI/UX 요구사항

### 5.1 시각적 요소
- 색상: 민트 그린 (주요), 파스텔 옐로우 (보조), 아이보리 화이트 (배경).
- 타이포그래피: 둥근 고딕체 (e.g., Spoqa Han Sans Neo).
- 형태: Rounded Corners, 귀엽고 직관적인 아이콘.

### 5.2 인터랙션 요소
- 애니메이션: Spring Effect (체크), Grow & Wobble (나무 성장), Slide Transition (페이지 전환).
- 꼬바기: 표정/모션 변화 (e.g., 점프, 윙크).

### 5.3 UX 라이팅
- 친근한 톤: 격려/공감 중심 (e.g., "꼬바기가 응원해요!").
- 오류: 문제 안내 시 긍정적 표현.

### 5.4 와이어프레임 요약
- **대시보드**: 상단 헤더, 꼬바기/메시지, 습관 체크 리스트, 습관 나무, 빠른 메뉴.
- **습관 설정**: 제목/아이콘, 목표/주기, 알림, 액션 버튼.
- **히스토리**: 기간 선택, 캘린더, 분석 차트, 꼬바기 회고.

## 6. 테스트 및 배포 요구사항

### 6.1 테스트
- 단위 테스트: 기능별 (e.g., 체크 로직).
- 통합 테스트: 애니메이션/알림 연동.
- 사용자 테스트: 베타 사용자 피드백 수집.

### 6.2 배포
- 환경: Web (React.js 추천), 백엔드 (Node.js 또는 Firebase).
- CI/CD: GitHub Actions 활용.
- 모니터링: 오류 추적 도구 (e.g., Sentry).
