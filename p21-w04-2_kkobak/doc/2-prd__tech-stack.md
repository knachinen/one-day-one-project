## 꼬박(Kkobak) 웹 프로토타입 구성을 위한 기술 스택 제안 (No-Signup/Frontend-Focused)

사용자가 **웹 서비스 가입 없이** 핵심 기능을 체험할 수 있도록 **프론트엔드 중심**의 기술 스택을 제안합니다. 이 구성은 '꼬박'의 핵심 가치인 **인터랙티브 애니메이션**과 **즉각적인 피드백**을 빠르게 구현하고, 사용자 데이터를 **클라이언트(브라우저)**에 저장하여 회원가입/로그인 과정의 복잡성 없이 바로 사용해 볼 수 있도록 초점을 맞춥니다.

### 1. 기술 스택 요약

|**영역**|**제안 기술 스택**|**선택 이유**|
|---|---|---|
|**프레임워크**|**Next.js (React)**|빠른 개발, 뛰어난 성능, 서버 컴포넌트(필요 시) 확장 용이성.|
|**상태 관리**|**Zustand**|가볍고 단순하여 프로토타입에 적합. 작은 번들 사이즈와 쉬운 러닝 커브.|
|**스타일/애니메이션**|**Tailwind CSS + Framer Motion**|직관적인 스타일링 및 '꼬박'의 활기찬 애니메이션(체크 피드백) 구현에 최적.|
|**데이터 저장**|**LocalStorage / IndexedDB**|**회원가입 없이** 사용자 데이터를 브라우저에 저장하여 즉시 사용 가능.|
|**차트**|**Recharts**|React 기반으로 제작되어 통합 용이. 상세 통계 라인 차트 구현에 적합.|
|**배포/호스팅**|**Vercel**|Next.js에 최적화된 배포 환경 제공, 빠른 CI/CD 구축.|

### 2. 세부 구성 및 프로토타입 적용 전략

#### 2.1 프론트엔드 (FE) 및 UI/UX

프로토타입은 대시보드 기능을 중심으로 구성하며, **꼬바기 마스코트 영역**과 **데일리 체크**의 인터랙션을 강조합니다.

- **즉각적 피드백 구현:**
    
    - **Framer Motion**을 사용하여 **체크마크 스프링 효과**, **꼬바기 박수 애니메이션**, **스트릭 갱신 불꽃 효과**, 그리고 달성률에 따른 꼬바기의 **표정/모션 변화**를 구현합니다.
        
    - **Tailwind CSS**의 유틸리티 클래스로 **미니멀**하고 **활기찬** UI 디자인 원칙을 빠르게 적용합니다.
        
- **습관 관리 및 시각화:**
    
    - **습관 생성** (FR-004) 및 **데일리 체크** (FR-007) 기능을 구현합니다.
        
    - **Recharts**를 활용하여 주간/월간 **달성률 도넛 차트** 또는 **퍼센트 표시** (FR-010)를 시각화합니다.
        

#### 2.2 데이터 및 상태 관리 (Focus on No-Signup)

**회원가입/로그인 기능 (FR-001, FR-002)을 생략**하고, 데이터를 클라이언트 측에서 관리합니다.

- **데이터 모델링:** `Habit` 및 `HabitRecord` 엔티티를 클라이언트 상태 및 저장소에 맞게 단순화하여 사용합니다.
    
- **상태 관리:** **Zustand**를 사용하여 습관 리스트와 현재 체크 상태를 전역적으로 관리합니다.
    
- **데이터 영속성:** `Habit`, `HabitRecord`, `Streak` 등의 사용자 데이터는 **LocalStorage** 또는 **IndexedDB**에 저장하여 사용자가 브라우저를 닫았다 열어도 기록이 유지되도록 합니다.
    
    - _(Note: LocalStorage는 단순하고 빠르지만, 저장 용량 제한과 동기화 제약이 있으므로, 데이터가 복잡해지면 IndexedDB로 전환을 고려할 수 있습니다.)_
        

#### 2.3 MVP 확장 대비

- **Next.js:** 향후 **Phase 1**의 **회원 관리** 기능이 추가될 경우, Next.js의 API Routes 또는 Server Components를 활용하여 백엔드와의 연동을 유연하게 진행할 수 있습니다.
    
- **FCM 알림 (Phase 1):** 푸시 알림 (FR-013)은 백엔드 서버가 필수이므로, 프로토타입 단계에서는 브라우저 알림 API를 활용한 **임시 알림** 또는 **Phase 1** 로드맵에 맞춰 백엔드 구축 시 **Firebase Cloud Messaging (FCM)** 연동을 계획합니다.
