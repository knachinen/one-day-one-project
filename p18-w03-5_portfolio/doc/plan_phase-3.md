## 🚀 3단계: 상태 관리 및 비동기 데이터 처리 상세 계획

**목표:** **Zustand**를 사용한 전역 상태 관리와 **TanStack Query**를 사용한 서버 상태(데이터) 관리를 구축하여, 프로젝트 필터링 및 데이터 표시 기능을 완성합니다.

|**작업 ID**|**작업 내용**|**상세 구현 방안**|**검증 및 완료 기준**|
|---|---|---|---|
|**3.1. 전역 상태 관리 환경 설정**|**Zustand v5.x**를 사용하여 전역 상태 관리용 `store`를 정의.|다크 모드(Theme), 모달 열림/닫힘 상태, 전역 알림(Toast) 등 UI 관련 상태를 포함하는 `useUIStore` 생성. **v5 마이그레이션 가이드**를 따라 `useShallow` 등을 사용하여 성능 최적화.|전역 상태를 사용하는 컴포넌트에서 상태 변경 시, 불필요한 리렌더링 없이 필요한 컴포넌트만 업데이트되는지 확인.|
|**3.2. Mock Data 구조 정의**|프로젝트 목록, 카테고리, 통계 카운터 등에 사용할 **Mock Data** 구조를 **TypeScript Interface**로 정의.|프로젝트 데이터 (`IProject[]`), 스킬 데이터 (`ISkill[]`) 등의 인터페이스를 `types.ts`에 명시. 2단계에서 배치한 정적 구조를 채울 임시 데이터(JSON) 생성.|`IProject` 인터페이스를 기반으로 Mock Data 배열이 오류 없이 생성되었는지 확인.|
|**3.3. 서버 상태 관리 환경 설정**|**TanStack Query v5.x** 설치 및 Provider 설정.|`/app/layout.tsx`에 `QueryClientProvider`를 설정하고, `QueryClient` 인스턴스를 생성하여 전역적으로 사용 가능하게 함.|앱이 로드될 때 TanStack Query의 Devtools가 정상적으로 표시되고 작동하는지 확인.|
|**3.4. 프로젝트 데이터 패칭 및 표시**|Mock Data를 비동기적으로 가져오는 **데이터 패칭 로직** 구현.|`useQuery` 훅을 사용하여 `Projects` 데이터를 패칭하는 `useProjects` 훅 생성. 로딩, 에러, 성공 상태를 분기하여 UI에 표시.|프로젝트 목록이 성공적으로 화면에 표시되며, 데이터 로딩 중에는 스켈레톤 UI가 출력되는지 확인.|
|**3.5. 프로젝트 필터링 로직 구현**|기획안의 요구사항에 맞는 **카테고리 필터링 및 검색 로직** 구현.|`useProjects` 훅 내에서 패칭된 데이터를 기반으로 필터링을 수행하는 함수 구현. 카테고리 상태는 `Zustand` 또는 `React State`로 관리.|필터 버튼 클릭 시, 해당 카테고리의 프로젝트만 실시간으로 표시되는지 (성능 저하 없이) 확인.|
|**3.6. 통계 카운터 동적 구현**|About 섹션의 **통계 카운터**(`프로젝트 수`, `고객 만족도` 등)를 동적으로 표시.|Mock Data 또는 서버 상태에서 데이터를 가져와 `useEffect`나 `Framer Motion`을 활용한 숫자 증가 애니메이션 효과를 적용 (애니메이션 로직은 4단계에서 완성).|카운터 값이 데이터 소스에 맞게 정확히 표시되는지 확인.|
|**3.7. Contact 폼 유효성 검사 구현**|문의하기 폼의 클라이언트 측 **유효성 검사** 로직 구현.|`React Hook Form` 또는 수동으로 이메일 형식, 필수 필드 누락 등을 검사하는 로직을 `onSubmit` 함수에 추가. 검사 실패 시 사용자에게 명확한 에러 메시지 표시.|이메일 형식을 틀리거나 필수 필드를 비워두고 제출 시, 에러 메시지가 표시되고 제출이 차단되는지 확인.|
|**3.8. 단위 테스트 (로직 검증)**|핵심 로직(필터링, 폼 유효성 검사)에 대한 **단위 테스트** 코드 작성.|**Jest** 또는 **Vitest**를 사용하여 3.5 및 3.7 작업에 대한 테스트 케이스를 작성하고 실행. (기획안 9.1 단위 테스트 반영)|`npm run test` 실행 시, 모든 로직 테스트가 통과하는지 확인.|
