
# 📱 LogStream (로그 스트림) 제품 요구사항 명세서

프로젝트명: LogStream (로그 스트림)
버전: 1.0 (MVP)
플랫폼: React Native / Expo (Android 전용)
작성일: 2025년 12월 06일
핵심 목표: ADB 권한이 부여된 환경에서 안드로이드 Logcat 데이터를 실시간으로 가져와 필터링 및 분석하는 개발자 전용 도구 제공.

## 1. 개요 및 목표

### 1.1. 제품 비전

복잡한 안드로이드 Logcat 출력을 모바일 환경에 최적화된 UI로 실시간 스트리밍, 필터링, 검색 및 분석을 제공하여, 현장에서 빠르고 효율적인 디버깅을 가능하게 하는 **전문 Log 분석 도구**.

### 1.2. MVP 핵심 목표

1. **네이티브 연동 검증:** Logcat 명령을 네이티브 모듈(Java/Kotlin)에서 실행하고, React Native의 JS 환경으로 **실시간 스트리밍**하는 핵심 기술의 구현 및 안정성 확보.
2. **필터링 성능:** 방대한 로그 데이터를 실시간으로 처리하고, Tag 및 Level 기반 필터링 시 **성능 저하 없이** 즉각적인 결과를 제공.
3. **진입 장벽 명시:** 앱의 핵심 기능 사용을 위해 필수적인 ADB **권한 부여 절차**를 사용자에게 명확하게 안내하는 UI/UX 구축.

## 2. 핵심 기능 및 요구사항 (Core Features)

### 2.1. 로그 데이터 획득 및 스트리밍 (Acquisition & Streaming)

|**ID**|**요구사항**|**세부사항 (기술적 난이도 상)**|
|---|---|---|
|F1.1|**실시간 스트리밍**|Android 네이티브 모듈을 개발하여 Logcat 명령을 백그라운드에서 실행하고, 파이프를 통해 로그 데이터를 React Native로 지속적으로 전달.|
|F1.2|**권한 부여 안내**|앱 실행 시 READ_LOGS 권한 상태를 확인하고, 권한 미보유 시 **"PC와 연결하여 다음 명령어를 실행하세요"**라는 문구와 함께 ADB 명령(`adb shell pm ...`)을 복사할 수 있는 UI 제공.|
|F1.3|**버퍼 선택**|사용자가 **main, events, radio** 중 하나 이상의 로그 버퍼를 선택하여 스트리밍할 수 있도록 UI 제공.|
|F1.4|**스트리밍 제어**|로그 캡처를 **시작/중지**할 수 있는 명확한 제어 버튼 제공.|

### 2.2. 로그 분석 및 필터링 (Analysis & Filtering)

|**ID**|**요구사항**|**세부사항**|
|---|---|---|
|F2.1|**레벨 필터링**|`Verbose`, `Debug`, `Info`, `Warning`, `Error`, `Fatal` 레벨별로 로그를 실시간으로 필터링하는 기능 제공.|
|F2.2|**태그 필터링**|사용자가 특정 Tag 이름을 입력하여 해당 Tag를 포함하는 로그만 표시하는 기능 제공. (AND/OR 조건은 MVP에서 제외)|
|F2.3|**텍스트 검색**|로그 메시지 내용 전체에서 특정 키워드를 검색하는 실시간 검색 기능 제공.|
|F2.4|**자동 스크롤**|로그 스트리밍 중에는 ListView가 자동으로 최신 로그 라인으로 이동해야 하며, 사용자가 수동으로 스크롤할 경우 자동 스크롤 기능은 일시 정지되어야 함.|

### 2.3. UI 및 데이터 영속성 (UI & Persistence)

|**ID**|**요구사항**|**세부사항**|
|---|---|---|
|F3.1|**가독성 UI**|각 로그 레벨에 따라 **다른 색상**을 적용하여 가독성을 극대화. (예: Error는 빨간색, Warning은 노란색)|
|F3.2|**로그 파일 저장**|수집 및 필터링된 로그를 로컬 Storage에 **.txt 형식**의 파일로 저장하는 기능 제공.|
|F3.3|**파일 공유**|저장된 로그 파일을 모바일 공유 시트를 통해 이메일, 클라우드 등으로 공유하는 기능 제공.|
|F3.4|**데이터 제한 및 성능**|UI에 표시되는 로그 라인 수를 **최대 5,000개**로 제한하고, `@shopify/flash-list` 등을 활용하여 대량의 텍스트 렌더링 시 **Stable 60fps**를 유지해야 함.|

## 3. 기술 스택 및 데이터 모델 (Tech Stack & Data Model)

### 3.1. 기술 스택

- **프론트엔드:** React Native
- **프레임워크:** Expo (Prebuild / Development Build 필수)
- **네이티브 연동:** Custom Native Module (Java/Kotlin 사용)
- **데이터 처리:** JavaScript 측에서 로그 파싱 및 필터링 수행
- **저장소:** Expo FileSystem (로그 파일 저장용)

### 3.2. 로그 데이터 모델 (Internal Data Structure)

로그 데이터는 네이티브 모듈에서 JSON 객체 배열로 JS 측에 전달됩니다.

|**필드**|**데이터 타입**|**설명**|
|---|---|---|
|timestamp|STRING|로그가 기록된 시각 및 날짜|
|level|STRING|로그 레벨 (V, D, I, W, E, F)|
|tag|STRING|로그를 기록한 모듈/클래스 Tag|
|pid|INTEGER|프로세스 ID|
|message|STRING|실제 로그 내용|

## 4. MVP 제외 기능 (Out of Scope for MVP - Phase 2)

- **루팅된 디바이스 전용 기능:** 커널 로그 버퍼 접근, CPU 사용량 등의 고급 시스템 정보 표시.
- **복합 필터링:** Tag와 Message를 동시에 검색하는 AND/OR 논리 필터링.
- **로그 하이라이트/마크:** 특정 라인을 강조 표시하거나 북마크하는 기능.
- **원격 스트리밍:** Wi-Fi 네트워크를 통해 PC 등으로 로그를 전송하는 기능.
