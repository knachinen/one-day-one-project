제공해주신 랜딩 페이지 기획안과 섹션별 디자인 명세서를 바탕으로, 안정성과 확장성을 고려한 **기술 스택 명세서**를 제안합니다.

## 🛠 기술 스택 제안 및 비교 명세서

### 1. 프론트엔드 (Frontend) 제안

랜딩 페이지는 **초기 로딩 속도(LCP)**와 **SEO(검색 엔진 최적화)**가 핵심이므로 SSR(서버 사이드 렌더링) 지원 여부가 중요합니다.

| 옵션 | 장점 | 단점 |
| --- | --- | --- |
| **Next.js (권장)** | **SEO 최적화**가 매우 뛰어나며, 정적 페이지 생성(SSG)으로 로딩 속도가 압도적으로 빠름. | React 기반의 숙련도가 필요하며 프로젝트 초기 설정이 다소 복잡할 수 있음. |
| **React (Vite)** | 컴포넌트 재사용성이 높고 생태계가 매우 방대하여 개발 속도가 빠름. | 클라이언트 사이드 렌더링(CSR) 특성상 SEO 설정에 별도의 라이브러리가 필요함. |

* **스타일링 (Styling):** **Tailwind CSS**를 권장합니다. 명세서에 정의된 그리드 시스템과 반응형 레이아웃(Desktop/Tablet/Mobile)을 유틸리티 클래스로 빠르게 구현할 수 있습니다.
* **애니메이션 (Animation):** **Framer Motion**. 히어로 섹션의 페이드인 및 카드 리프트업 효과 등 마이크로 인터랙션을 부드럽게 구현하기에 최적입니다.

---

### 2. 백엔드 (Backend) 제안

상담 신청 폼의 데이터 처리와 향후 서비스 확장성을 고려한 비교입니다.

| 옵션 | 장점 | 단점 |
| --- | --- | --- |
| **Node.js (NestJS) (권장)** | 프론트엔드와 동일한 언어(TypeScript)를 사용하여 개발 효율성이 높고 실시간 데이터 처리에 강함. | 고도의 연산 작업이 필요한 경우 성능 한계가 있을 수 있음. |
| **Python (FastAPI)** | 문법이 간결하여 API 서버 구축 속도가 매우 빠르고 비동기 처리에 효율적임. | 대규모 아키텍처 설계 시 NestJS에 비해 엄격한 구조화가 부족할 수 있음. |

* **데이터베이스 (Database):** **PostgreSQL**. 상담 신청 정보 및 고객 지표 데이터를 구조화하여 안전하게 관리하기 적합합니다.
* **인프라 (Infrastructure):** **Vercel** (프론트엔드 호스팅) 및 **AWS** (백엔드/DB). 자동 배포(CI/CD) 환경 구축에 최적화되어 있습니다.

---

### 3. 최종 확정 기술 스택 요약

| 분류 | 기술 스택 | 비고 |
| --- | --- | --- |
| **Language** | TypeScript | 코드 안정성 및 유지보수성 확보 |
