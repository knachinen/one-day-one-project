# 메모앱 랜딩페이지 기획안

## 1. 목적 및 목표

- **목적**: 메모앱의 핵심 가치를 직관적으로 전달하고, 체험 중심의 인터랙션으로 전환(다운로드/가입)을 유도
    
- **KPI**: CTA 클릭률, 체험 완료율, 스크롤 도달률, 전환율
    

---

## 2. 타겟 사용자

- 빠르게 기록하고 정리하고 싶은 직장인/학생
    
- 복잡한 기능보다 **즉시성·간결함**을 선호하는 사용자
    

---

## 3. 핵심 메시지

- "생각이 떠오르는 순간, 바로 메모"
    
- "정리까지 자동으로"
    

---

## 4. 전체 정보 구조 (IA)

1. 히어로 섹션 (첫 인상 + 즉시 체험)
    
2. 핵심 기능 소개 (문제 → 해결)
    
3. 인터랙티브 데모 섹션
    
4. 사용 시나리오
    
5. 신뢰 요소 (후기/숫자)
    
6. CTA (다운로드/시작하기)
    

---

## 5. 섹션별 상세 기획

### 5.1 히어로 섹션

**구성 요소**

- 헤드라인 + 서브카피
    
- 가짜 메모 입력창 (인터랙티브)
    
- 메인 CTA 버튼
    

**인터랙티브 요소**

- 사용자가 입력창에 타이핑하면 실제 메모처럼 글자가 입력됨
    
- 엔터 입력 시 메모 카드가 생성되며 아래로 쌓임
    

**애니메이션 요소**

- 페이지 진입 시 메모 카드가 **페이드 인 + 슬라이드 업**
    
- 커서 깜빡임 애니메이션으로 실제 입력 느낌 강화
    

---

### 5.2 핵심 기능 소개 섹션

**구성 요소**

- 기능 3~4개 (빠른 기록, 자동 정리, 검색, 동기화)
    
- 아이콘 + 짧은 설명
    

**인터랙티브 요소**

- 카드 호버 시 기능 미리보기 툴팁 노출
    
- 클릭 시 해당 기능 데모로 스크롤 이동
    

**애니메이션 요소**

- 스크롤 트리거 기반 **스태거(stagger) 애니메이션**
    
- 아이콘 마이크로 인터랙션 (살짝 확대 후 복귀)
    

---

### 5.3 인터랙티브 데모 섹션 (핵심)

**구성 요소**

- 실제 앱 UI와 유사한 데모 화면
    
- 안내 문구 ("한 줄 메모를 입력해보세요")
    

**인터랙티브 요소**

- 사용자가 직접 메모 입력 가능
    
- 태그(#업무, #아이디어) 자동 추천 클릭 가능
    
- 체크박스/할 일 토글 체험
    

**애니메이션 요소**

- 입력 완료 시 메모가 카드로 변환되며 자연스럽게 정렬
    
- 태그 선택 시 컬러 하이라이트 애니메이션
    

---

### 5.4 사용 시나리오 섹션

**구성 요소**

- 상황별 탭 (회의 중 / 공부 중 / 아이디어 스케치)
    

**인터랙티브 요소**

- 탭 클릭 시 해당 시나리오 화면 전환
    

**애니메이션 요소**

- 탭 전환 시 **슬라이드 + 페이드 크로스 전환**
    
- 화면 내 요소는 짧은 딜레이로 순차 등장
    

---

### 5.5 신뢰 요소 섹션

**구성 요소**

- 사용자 후기 카드
    
- 사용 지표 (누적 메모 수, 활성 사용자 수)
    

**인터랙티브 요소**

- 후기 카드 드래그/스와이프
    

**애니메이션 요소**

- 숫자 카운트업 애니메이션
    
- 후기 카드 자동 슬라이드 (호버 시 정지)
    

---

### 5.6 CTA 섹션

**구성 요소**

- 강력한 한 문장 메시지
    
- 다운로드 / 시작하기 버튼
    

**인터랙티브 요소**

- 버튼 호버 시 색상 + 쉐도우 변화
    

**애니메이션 요소**

- CTA 영역 진입 시 배경 그라데이션 천천히 움직임
    

---

## 6. 공통 인터랙션 & 애니메이션 가이드

### 인터랙션 원칙

- 클릭보다 **입력·체험 중심**
    
- 즉각적인 피드백 제공
    

### 애니메이션 원칙

- 300ms 이내의 짧고 부드러운 전환
    
- 과한 효과보다 **의미 있는 움직임**
    

---

## 7. 기술 스택 제안 (옵션)

- 인터랙션/애니메이션: Framer Motion / GSAP
    
- 데모 구현: React + 상태 기반 UI
    

---

## 8. 기대 효과

- 단순 소개 페이지 대비 체류 시간 증가
    
- 앱 사용 경험을 미리 제공하여 전환 장벽 감소
    

---

_본 기획안은 MVP 랜딩페이지 기준으로, 기능 확장에 따라 인터랙션을 단계적으로 추가 가능_

# 메모앱 랜딩페이지 제품 요구사항 명세서(PRD)

## 1. 문서 개요

### 1.1 목적

본 문서는 **메모앱 랜딩페이지** 구현을 위한 제품 요구사항을 정의한다. 기획안에 정의된 인터랙티브 요소와 애니메이션을 실제 제품 수준으로 구현하기 위한 기준을 제공한다.

### 1.2 범위

- 대상: 메모앱 **마케팅/체험용 랜딩페이지 (Web)**
    
- 제외: 실제 메모 데이터 영구 저장, 로그인 이후 앱 내부 기능
    

### 1.3 성공 지표 (KPI)

- CTA 클릭률 ≥ 5%
    
- 인터랙티브 데모 완료율 ≥ 40%
    
- 평균 체류 시간 ≥ 90초
    

---

## 2. 사용자 정의

### 2.1 주요 사용자(Persona)

|유형|특징|니즈|
|---|---|---|
|직장인|회의/업무 메모 빈번|빠른 기록, 정리 자동화|
|학생|강의/공부 메모|검색, 태그 정리|
|크리에이터|아이디어 스케치|즉시 기록, 시각적 정리|

---

## 3. 사용자 여정(User Journey)

1. 랜딩페이지 진입
    
2. Hero 영역에서 메모 작성 경험
    
3. 기능/시나리오 탐색
    
4. 신뢰 요소 확인
    
5. CTA 클릭 (다운로드/가입)
    

---

## 4. 기능 요구사항 (Functional Requirements)

### FR-01 Hero 메모 데모

- 사용자는 실제 입력 없이도 자동 타이핑 메모 데모를 볼 수 있어야 한다
    
- 메모 내용은 3가지 시나리오 문구를 순환한다
    
- 데모는 사용자의 입력 시 즉시 중단되고 사용자 입력을 우선한다
    

---

### FR-02 기능 소개 인터랙션

- 기능 카드는 스크롤 시 순차적으로 노출되어야 한다
    
- 카드 호버 시 미리보기 애니메이션이 실행되어야 한다
    
- 기능 전환 시 UI 미리보기 화면이 변경되어야 한다
    

---

### FR-03 사용 시나리오 탐색

- 사용자는 탭 또는 드래그로 시나리오를 전환할 수 있어야 한다
    
- 시나리오 선택 시 관련 화면이 즉시 반영되어야 한다
    
- 모바일 환경에서는 스와이프 인터랙션을 지원해야 한다
    

---

### FR-04 후기 및 신뢰 요소

- 후기 카드는 자동 슬라이드 되어야 한다
    
- 사용자는 네비게이션으로 직접 이동할 수 있어야 한다
    
- 지표 숫자는 페이지 진입 시 애니메이션으로 증가한다
    

---

### FR-05 CTA 전환 기능

- 이메일 입력 시 실시간 유효성 검사를 수행한다
    
- 제출 성공 시 성공 애니메이션을 노출한다
    
- 중복 제출은 제한해야 한다
    

---

## 5. 인터랙션 & 애니메이션 요구사항

### AR-01 공통 애니메이션 규칙

- 모든 애니메이션은 200~400ms 이내
    
- ease-in-out 기본 사용
    
- 사용자 입력을 방해하지 않아야 한다
    

### AR-02 스크롤 트리거

- 뷰포트 60% 진입 시 애니메이션 실행
    
- 재스크롤 시 중복 실행 여부는 섹션별로 제어
    

---

## 6. 비기능 요구사항 (Non-Functional Requirements)

### NFR-01 성능

- 초기 로딩 시간 ≤ 2초 (LCP 기준)
    
- 애니메이션 프레임 드랍 없음 (60fps 목표)
    

### NFR-02 접근성

- 키보드 네비게이션 가능
    
- prefers-reduced-motion 설정 시 애니메이션 최소화
    

### NFR-03 반응형

- Desktop / Tablet / Mobile 지원
    
- 모바일 퍼스트 레이아웃
    

---

## 7. 기술 요구사항

- Framework: React (Next.js 권장)
    
- Animation: Framer Motion 또는 GSAP
    
- State: Local UI State 기반
    
- Asset: SVG / Lottie
    

---

## 8. 제약사항 및 리스크

|항목|설명|
|---|---|
|과도한 애니메이션|성능 저하 위험|
|모바일 성능|저사양 기기에서 렉 가능|
|구현 복잡도|인터랙션 범위 증가 시 일정 리스크|
