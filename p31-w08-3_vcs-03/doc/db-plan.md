# 📌 데이터베이스 활용 기획안

### *“포트폴리오 자체가 CMS처럼 동작하는 구조”*

---

## 1. 기획 목적

정적 포트폴리오의 한계를 넘어
**콘텐츠를 코드 수정 없이 관리**하고,
**프로젝트가 늘어나도 유지보수 비용이 거의 없는 구조**를 만든다.

> ❌ 매번 프로젝트 추가할 때 코드 수정
> ✅ 관리자 페이지에서 추가 → 즉시 포트폴리오 반영

---

## 2. 전체 아키텍처 개요

```
[Admin Page]
   ↓ (CRUD)
[Supabase DB]
   ↓ (Fetch)
[Public Portfolio Pages]
```

* **Supabase**: 데이터 저장 + 인증
* **Next.js(App Router)**: 화면 렌더링
* **Portfolio = CMS + Showcase** 역할 동시 수행

---

## 3. 데이터베이스 테이블 설계

### 3.1 `projects` 테이블

| 컬럼명        | 타입        | 설명                          |
| ---------- | --------- | --------------------------- |
| id         | uuid (PK) | 프로젝트 고유 ID                  |
| title      | text      | 프로젝트명                       |
| summary    | text      | 한 줄 요약                      |
| role       | text      | 담당 역할                       |
| tech_stack | text[]    | 사용 기술 (배열)                  |
| thumbnail  | text      | 대표 이미지 URL                  |
| status     | text      | `in_progress` / `completed` |
| created_at | timestamp | 생성일                         |

---

### 3.2 `project_images` 테이블

| 컬럼명        | 타입        | 설명             |
| ---------- | --------- | -------------- |
| id         | uuid (PK) | 이미지 ID         |
| project_id | uuid (FK) | projects.id 참조 |
| image_url  | text      | 이미지 URL        |
| order      | int       | 이미지 순서         |

> ✔ 프로젝트 1개 : 이미지 N개 (1:N 관계)

---

## 4. 데이터 활용 시나리오

### 4.1 프로젝트 목록 (Work 페이지)

**조회 로직**

* `projects` 테이블 조회
* `status = completed` 기본 필터
* 최신순 정렬 (`created_at DESC`)

**표현 요소**

* thumbnail
* title
* summary
* tech_stack (태그 형태)

---

### 4.2 프로젝트 상세 페이지

**조회 로직**

* 프로젝트 1건 조회
* 해당 `project_id` 기준으로 `project_images` 조회

**표현 요소**

* 프로젝트 설명
* 역할 / 기술 스택
* 이미지 갤러리 (order 기준 정렬)

---

## 5. 핵심 활용 포인트

### 5.1 관리자 페이지 (Internal CMS)

**기능**

* 프로젝트 추가
* 프로젝트 수정
* 상태 변경 (진행중 ↔ 완료)
* 이미지 업로드 & 순서 조정

**의미**

* 포트폴리오 ≠ 정적 웹
* **운영 가능한 서비스**로 진화

---

### 5.2 기술 스택 필터링

**구현 방식**

* `tech_stack` 배열 활용
* 예: `"Next.js"` 포함 프로젝트만 조회

**UX**

* 상단 필터 버튼

  * React
  * Next.js
  * Supabase
* 다중 선택 가능 구조

---

### 5.3 진행중 / 완료 프로젝트 분리

**활용 예**

* Work 페이지 상단: 완료 프로젝트
* 하단 또는 별도 섹션: 진행중 프로젝트

**장점**

* 현재 활동 중임을 자연스럽게 어필
* 업데이트가 멈춘 포트폴리오 인상 방지
